<a id="BUG-1"></a>
## BUG-1. Сообщение о минимальной длине пароля называет неверное число

- **Приоритет:** Средний
- **Воспроизводимость:** 100 %
- **Автотест:** `passwordOfClaimedMinimumLengthIsAccepted`

### Шаги воспроизведения

1. Открыть https://practicesoftwaretesting.com/auth/register
2. Ввести в поле пароля шесть символов, например `Aa1!bc`
3. Перевести фокус на другое поле

### Ожидаемый результат

Пароль принимается: сообщение об ошибке обещает минимум шесть символов.

### Фактический результат

Под полем остаётся `Password must be minimal 6 characters long.` Порог
срабатывает на восьми символах: значения 5, 6 и 7 отклоняются, 8 принимается.
API подтверждает ту же границу — `POST /users/register` с семисимвольным
паролем отвечает `422` и текстом `The password field must be at least
8 characters.`

### Почему это важно

Пользователь следует прямому указанию сообщения, вводит шесть символов и
получает то же самое сообщение снова. Подсказка не помогает исправить ввод,
а вводит в заблуждение. Ошибаются не проверка и не API — ошибается текст.

<a id="BUG-2"></a>
## BUG-2. Афганистан отсутствует в списке стран

- **Приоритет:** Средний
- **Воспроизводимость:** 100 %
- **Автотест:** `countryListContainsAfghanistan`

### Шаги воспроизведения

1. Открыть форму регистрации
2. Раскрыть список «Your country»

### Ожидаемый результат

249 стран по ISO 3166-1 alpha-2, первая по алфавиту — Afghanistan.

### Фактический результат

В списке 249 пунктов, но первый из них — заглушка «Your country \*», то есть
стран 248. Список начинается с Albania, Afghanistan отсутствует.

### Почему это важно

Житель страны не может завершить регистрацию: поле обязательное, подходящего
значения в нём нет.

<a id="BUG-3"></a>
## BUG-3. Åland Islands нарушает алфавитный порядок

- **Приоритет:** Низкий
- **Воспроизводимость:** 100 %
- **Автотест:** `countryListIgnoresDiacriticsWhenSorting`

### Шаги воспроизведения

1. Открыть форму регистрации
2. Раскрыть список стран и посмотреть на первые пункты

### Ожидаемый результат

`Åland Islands`, `Albania`, `Algeria`: при сортировке без учёта диакритики
`Ala` идёт раньше `Alb`.

### Фактический результат

`Albania`, `Åland Islands`, `Algeria`. Символ `Å` при сортировке приравнен
не к `A`, а к чему-то другому, из-за чего страна оказывается между двумя
соседями вместо места перед ними.

<a id="BUG-4"></a>
## BUG-4. Версия в подвале расходится с версией в заголовке

- **Приоритет:** Низкий
- **Воспроизводимость:** 100 %
- **Автотест:** `footerVersionMatchesTitle`

### Шаги воспроизведения

1. Открыть любую страницу магазина
2. Сравнить заголовок вкладки и текст в подвале

### Ожидаемый результат

Версия одна и та же.

### Фактический результат

Заголовок вкладки: `Practice Software Testing - Toolshop - v5.0`.
Подвал: `v2.4 | Built 2026-08-22 | Angular 20.0.5`.

### Почему это важно

По версии в подвале определяют, что именно развёрнуто на стенде. Расхождение
делает баг-репорты неточными: непонятно, к какой версии относить находку.

<a id="BUG-5"></a>
## BUG-5. Бренды, товары и категории создаются без авторизации

- **Приоритет:** Высокий
- **Воспроизводимость:** 100 %
- **Автотест:** `anonymousBrandCreationIsRejected`

### Шаги воспроизведения

```bash
curl -s -o /dev/null -w "%{http_code}\n" \
  -X POST https://api.practicesoftwaretesting.com/brands \
  -H "Content-Type: application/json" \
  -d '{"name":"qa-probe","slug":"qa-probe"}'
```

### Ожидаемый результат

`401 Unauthorized`: создание справочных сущностей — операция администратора.

### Фактический результат

`201 Created`. То же самое верно для `POST /products` и `POST /categories`,
а также для `PUT` и `PATCH` этих ресурсов. В схеме OpenAPI у них
`security: null`, тогда как у `DELETE` авторизация требуется.

### Почему это важно

Последствие уже видно на витрине: в фильтре брендов лежат пять записей
`some name`, заведённых посторонними. Любой посетитель может засорить каталог
и справочники магазина, а удалить их не сможет — на удаление права нужны.

Побочный эффект для тестирования: ни точное число товаров, ни состав списка
брендов нельзя использовать в проверках, потому что их меняет кто угодно.

<a id="BUG-6"></a>
## BUG-6. Пустой пароль обвиняется в недопустимых символах

- **Приоритет:** Низкий
- **Воспроизводимость:** 100 %
- **Автотест:** `emptyPasswordIsNotBlamedForInvalidCharacters`

### Шаги воспроизведения

1. Открыть форму регистрации
2. Отправить её, не заполняя ничего

### Ожидаемый результат

Под полем пароля одно сообщение: `Password is required`.

### Фактический результат

Три сообщения одновременно:

```
Password is required
Password must be minimal 6 characters long.
Password can not include invalid characters.
```

Последнее бессмысленно: в пустой строке нет символов, ни допустимых,
ни запрещённых. Проверки формата применяются к незаполненному полю вместо
того, чтобы уступить проверке на обязательность.

## BUG-7. Пустая дата рождения даёт два сообщения сразу

- **Приоритет:** Низкий
- **Воспроизводимость:** 100 %
- **Автотест:** `emptyDateOfBirthReportsSingleMessage`

### Шаги воспроизведения

1. Открыть форму регистрации
2. Отправить её, не заполняя ничего

### Ожидаемый результат

Под полем даты рождения одно сообщение: `Date of Birth is required`.

### Фактический результат

Два сообщения:

```

Date of Birth is required
```

Первое противоречит второму: поле не заполнено, и претензия к формату к нему
не относится. Причина та же, что у [BUG-6](#BUG-6).

<a id="BUG-8"></a>
## BUG-8. Заказ подтверждается с пустыми реквизитами карты

- **Приоритет:** Высокий
- **Воспроизводимость:** 100 %
- **Автотест:** `emptyCreditCardBlocksConfirmation`

### Шаги воспроизведения

1. Добавить любой товар в корзину, открыть оформление
2. Пройти шаги «Cart» и «Sign in» (годится «Continue as Guest»)
3. Заполнить адрес доставки и перейти к оплате
4. Выбрать способ оплаты «Credit Card»
5. Не заполнять ни одно поле карты и нажать «Confirm»

### Ожидаемый результат

Кнопка «Confirm» заблокирована, пока реквизиты не заполнены, — так ведут себя
остальные способы оплаты: у Bank Transfer, Gift Card и Buy Now Pay Later
пустые поля подтверждение блокируют.

### Фактический результат

Все четыре поля карты помечены как валидные, кнопка доступна, нажатие даёт
красное сообщение `Unknown error`. Ни одно поле не подсвечено, пользователю
не сообщают, чего не хватает.

### Причина

У полей карты есть проверка формата, но нет проверки на обязательность.
Пустая строка формат не нарушает, поэтому форма считается заполненной.
Проверяется это легко: частично заполненная карта блокирует кнопку,
а полностью пустая — нет.

### Почему это важно

Пользователь оказывается в тупике: заказ не оформляется, а сообщение
не подсказывает, что исправить.
