# Тест-кейсы: витрина и оформление заказа Toolshop

- **Объект тестирования:** веб-интерфейс магазина Toolshop
- **Стенд:** https://practicesoftwaretesting.com
- **Автор:** Гавриков Т. М.
- **Дата:** 25.08.2026

Откуда взялись наборы данных — в [test-design.md](test-design.md).
Найденные дефекты — в [bug-report.md](bug-report.md).

## Предусловия

1. Стенд доступен, каталог отвечает.
2. Пользователь, которому нужен вход, заводится через `POST /users/register`:
   заполнение формы из двенадцати полей ради предусловия сделало бы тест
   зависимым от чужого дефекта.
3. Товар ищется по названию через `GET /products`. Идентификаторы в тесты
   не зашиты: стенд периодически пересоздаёт базу и меняет их разом.

## Подробности отдельных кейсов

### ТК-03. Незнакомый адрес не выдаёт существование аккаунта

**Шаги.** Открыть страницу входа, ввести незарегистрированный адрес и
случайный пароль, отправить форму.

**Ожидание.** Сообщение `Invalid email or password` — ровно такое же, как при
верном адресе с неверным паролем.

**Зачем.** Разные сообщения позволили бы перебором выяснить, какие адреса
заведены в магазине.

### ТК-04. Пустая форма сообщает обо всех обязательных полях

**Шаги.** Открыть форму регистрации и отправить её пустой.

**Ожидание.** Каждое из двенадцати полей показывает своё сообщение.

**Особенность.** Кейс проверяется одной отправкой формы и мягкими
проверками: двенадцать отдельных тестов двенадцать раз открывали бы страницу
ради одного действия, а мягкие проверки показывают сразу все расхождения,
а не только первое.

### ТК-10. Порядок держится при любом сочетании фильтров

**Шаги.** Для каждого из шести попарных сочетаний: выбрать категорию, бренд,
признак экологичности, задать сортировку по цене, дождаться перерисовки.

**Ожидание.** Цены идут по возрастанию или убыванию в соответствии с
выбранной сортировкой.

**Особенность.** Если после фильтрации осталось меньше двух товаров,
проверять порядок не на чем, и кейс завершается без утверждений.

### ТК-13. Изменение количества пересчитывает стоимость

**Шаги.** Добавить товар, открыть корзину, задать количество 3.

**Ожидание.** Стоимость строки равна цене товара, умноженной на три. Цена
берётся со страницы, а не из константы: стенд её меняет.
